# Godot 4.3+ 物品与交易系统

使用 Godot 导入本目录的 project.godot，运行即可打开背包测试与 GM 面板。未修改工作区已有项目。

## 自动化验证

```powershell
godot --headless --path . --editor --import --quit
godot --headless --path . res://tests/test_item_system.tscn
```

测试无需插件，覆盖添加/移除、堆叠、重量、原子失败、真实合成概率及双方交易。成功退出码为 0。

## 配置与热重载

所有游戏平衡数值在 resources 下 JSON 中。settings.json 管理容量、承重、周期、占位颜色、轮询和测试参数；items 与 recipes 目录支持多个 JSON。代码中的 0/1 等表示空值、索引、单位物品与边界，不是平衡参数。

编辑资源 JSON 后按配置周期检查内容哈希；GM 支持物品及配方手动重载。导出文件在 Godot 用户数据目录 config_backup.json。数据文件通过 JSON 验证后整体替换；不要在编辑配置时删除仍被背包引用的物品 ID。背包既有容量保持创建时设置，物品重量更新即时生效，超重或旧堆叠超过新上限的背包可以通过移除逐步恢复，移除不会重排或截断剩余物品。图标路径全部配置为占位，后续填入 res:// 纹理路径即可；替换美术后可手动重载数据库清缓存。

## 合成与时间

调用 `await CraftingSystem.attempt_craft(id, inventory)`。required_day 为指定的确切日期，0 为任意日期。时间段含两端并支持跨午夜。催化剂消耗一个，失败产物使用 output_count。仅概率非零的结果分支必须有容量。等待期间不预扣材料，结束时重新检查，该配方内容改变则取消（无关配置或相同内容重载不取消），不产生物品或消耗。相同背包不能同时发起多个合成。周期到最后一天不自动回到第一天。

## 交易与多人集成

先由可信服务器调用 `register_player(player_id, inventory, location)`，移动时更新 locations。双方必须在同一交易所；交易时间左闭右开。报价修改会清除双方锁定，count 为报价总量，0 删除报价。超时自动取消。

提交在同一帧中完成两背包校验和交换，提交后才发信号。信仰点按普通可交易物品报价，没有隐含汇率或手续费。

这是可运行的本地系统与服务器逻辑模块，未实现六人联网传输、身份认证、存档或完整生存玩法。联网时必须只允许服务器持有/修改权威背包，通过已认证 RPC 映射玩家 ID，禁止客户端任意调用注册、直接修改报价或游戏状态。GM 面板只接入开发构建。

## 审查修复与回归

通用配置只在必需字段、字段类型和数值边界均有效时提交；无效热重载会警告并保留有效版本。背包提交先构建完整候选格子，验证失败不会清空既有内容。

回归测试新增：降低堆叠上限后的无损移除、非法提交原子性、遗漏字段/零值/错误类型/非法时间与颜色校验、无效配置热重载保留旧版本、0%/100% 合成容量边界、配方相同内容重载及实际变化期间的合成处理。无效配置测试会产生一条预期警告，并在同一帧恢复原文件。
